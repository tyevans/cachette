## Why

The head-up display draws text into a framebuffer. Its tests read the numbers
the panel holds, and they check that everything the panel paints stays inside
the rectangle the panel states.

They do not check that the panel is readable. A value that overruns its
column is cut, so it stays inside the rectangle and says the wrong thing. A
row that overlaps the row under it stays inside the rectangle too. Both are
layout defects, both are silent, and one of them already happened during the
first build: a row of two counts ran past the panel edge, and only a rendered
picture showed it.

The window is not the answer. A window needs a display, and continuous
integration has none. The painting is separable from the showing, which is why
every viewer test paints into a canvas and none opens a window.

## Impact review

**Governed by.** ADR-0067 D1 requires that the drawing and the reporting hold
a shared reference to the world. The test draws a frame, so it holds the world
by a shared reference and writes nothing to it. ADR-0067 D3 puts the floating
point boundary at the viewer, so the test carries the same allowance that the
other viewer tests carry. ADR-0070 D1 says the panel adds no pass over the
world. The work adds no reader of the world, so the decision is untouched.

**Changes.** None. No record changes.

**Creates.** None. The three-condition test for a record refuses one here.[^1]
A future contributor could reasonably choose a different form of stored
picture, so the first condition holds. The second does not: a stored picture
is regenerated by one command, so a different form costs little later. The
reasoning is in the test module, where a reader of the test sees it, so the
third does not hold either.

**Blockers.** None. BLK-007 holds every cost figure, and the panel prints two
cost rows. The fixture states those figures rather than measuring them, so the
work invents no cost figure and claims no measurement.[^2]

**Precedent.** FND-051 and FND-048 record that a fixture which models the
typical case never supplies the input that fails the assertion.[^3] The
fixture here must therefore draw a panel with real content: soldiers of every
faction inside the window, a region under the crosshair, and every section of
the panel present.

**The form of the picture.** A picture of the whole frame changes whenever the
terrain colours change, so it would fail on an unrelated commit. The picture
is therefore of the panel's ink alone. Each pixel becomes one character. A
pixel the panel left alone, and a pixel the panel only shaded, become the
ground character. Every other pixel takes the character of the colour it was
written in. The picture is the difference between a canvas with the panel and
a canvas without it, so no ground colour reaches it.

**The fixed readout.** Two rows of the panel divide by a wall clock span, so
no picture of them could repeat. The measurement type gains a constructor that
states the figures instead of reading a clock. The span has one declaration
site, so the two sources cannot disagree.[^4]

**The failure.** A message that says the pictures differ is not usable. The
test writes the picture it got, as characters and as an image, names the first
row that differs, and states the command that writes the stored picture again.

## Done when

- A test draws the whole frame and compares the panel's ink against a picture
  it read from a file. It does not compute the expected picture.[^5]
- The picture is regenerated by one documented command, and the failure
  message states that command.
- A failure writes the picture it got, as characters and as an image.
- The fixture draws a panel with every section, with four legend rows that
  hold counts above zero, and with a region under the crosshair.
- Three layout defects put back into the source each make the test fail. Two
  of the three pass every other test in the crate.
- The image writer has one call site for the example and for the test.
- The whole check command runs green.

## Outcome

The work landed as planned. Nothing in the impact review changed.

A test draws the whole frame into two canvases, one with the panel and one
without it. It turns the difference into a picture of characters, and it
compares that picture against a file. It reads the expected picture and never
computes it.

The measurement type gained a constructor that states its figures instead of
reading a clock. The wall clock span now has one declaration site, so the
running source and the fixed source cannot disagree.

The image writer moved out of the example into the viewer crate. The example
and the failure path of the test now share it.

Three defects were put back into the source, one at a time, to prove the test
can fail. Two of the three passed every other test in the crate. The commit
body names them and says how many tests caught each.

One property of the picture is worth stating, because it decides when a person
must look at it. The picture holds no ground colour, so a change to the
terrain colours leaves it alone. It does hold the counts the panel prints, so a
change to what the window holds does change it. That is a change to what the
panel says, and a person must read it before writing the picture again.

No register entry moved. The work opened no blocker, closed none, and
corrected nothing the project believed.
