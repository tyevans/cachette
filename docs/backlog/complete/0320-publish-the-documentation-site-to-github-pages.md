## Why

**The documentation site was built and it published nowhere.** A job built the
site on every run and kept the result as an artefact. A second job would have
published it, and it did nothing, because no file in the tree could say where
the site answers.[^1]

**A blocker held two facts.** The first was the address of the site. The second
was the hosting source setting, which the host reads from a setting of the
repository rather than from a file.[^2] The item that built the job stated the
address as a parameter and cited that row.[^3]

**The project owner named the host on 3 September 2026.** The site publishes to
GitHub Pages. This repository does not carry the name of its owner, so the site
is a project site and it answers on a path below the host name of the owner.
That is one fact, and it closes the first half of the row.

**A developer who builds a game on this engine needs the reference to answer at
an address.** A product record states the need and names the audience.[^4] A
built artefact that nobody can open answers nothing.

## Impact review

**Governed by.** ADR-0107 D4.[^5]

**D1, the reference is generated by an import of the compiled module.** This
item changes no source of the reference. The build still imports the compiled
module, and the check still derives its expectation from that import.

**D2 and D3, where the prose lives.** This item writes no prose for a member of
the compiled module, and it does not touch the type stub.

**D4, the job builds the extension before the site and fails when the import
fails.** This item weakens neither half. The build job is unchanged, the probe
recipe is unchanged, and both still run before anything publishes. The publish
job runs after the build job and only after it passes.

**Changes.** No record changes.

**Creates.** No record. One row in the decisions register holds the choice this
item made about the switch of the publishing job.[^6]

**Blockers.** The row that held this work is resolved by this item.[^2] No other
blocker governs it. No page this item publishes states a cost figure.

**Findings.** Two.[^7] [^8]

## What the work did

**It stated the address in the site configuration.** The configuration is the
one declaration site of the address. The builder writes it into the canonical
link of every page, into the sitemap, and into the page the host serves for an
address it does not hold.

**It removed the switch of the publishing job.** The job now publishes on every
push to the main branch, and it carries no repository variable. The hosting
source setting is the switch, and the deploy step reads it. The decisions
register holds the reasoning and the option it rejected.[^6]

**It swept the tree for the number of the blocker** and repaired every document
that called the row open.

## What it did not do

It did not write a tutorial, a how-to guide or an explanation page. Three
separate items hold those.

It did not turn the publishing on. That is one setting of the repository, and
only the project owner can change it. One item holds the action and the check
that follows it.[^9]

It did not move the documentation build into the whole check command. A row in
the decisions register holds that choice, and it now has the address it waited
for.[^10]

## Done when

- The site configuration states the address, and no other file states it.
- The published page carries a canonical link that names the address, and the
  sitemap lists every page under it.
- The page the host serves for an unknown address links inside the site, and
  not to the root of the domain.
- The publishing job runs on the main branch and carries no switch of its own.
- The build job and the probe recipe are unchanged, and both still fail in
  every case they failed in before.
- No document in the tree calls the blocker open.
- The whole check command runs green.

## Outcome

**Every statement above holds.** The site builds, and the report of the build
says that every one of the summaries the import found reached the site. The
probe still fails the job in both of its cases.

**The address changed one page that nobody expected it to change.** The page
the host serves for an unknown address cannot use a relative link, so the
builder writes an absolute path into every link of it and derives that path
from the address. With no address it wrote the root of the domain, which is
outside a project site. A finding holds the evidence.[^7]

**The blocker closed on the fact and not on the action.** The row asked for the
address and for a confirmation that the hosting was on. The first is
information and the register holds information. The second is an action in a
browser, and it now sits in the backlog. A finding holds that
distinction.[^8]
