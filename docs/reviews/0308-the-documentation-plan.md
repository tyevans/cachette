# Working Report — 0308, the documentation plan

This document reports the work that wrote one backlog item and the seven items
under it. It is a record of one moment, and nobody maintains it.

Date of the work: 3 September 2026.

## 1. The shape of the plan, and why

The plan uses Diátaxis, which splits documentation into four kinds by what the
reader is doing.[^1] The four are mapped onto the surface that exists, not onto
a template. The surface was read first: the package entry point and the twelve
names it re-exports, the agent server and its session store, the demonstration
window and its drawing surface, and the type stub.[^2]

**The reference is a build, and it is the whole of one quadrant.** A record
binds it: the published reference comes from an import of the compiled module,
the prose lives in the Rust doc comment, and the job fails when the import
fails.[^3] So the plan never asks anybody to write a page of interface prose.
It plans a job and it plans the doc comments behind it.

**The tutorial is one page.** The smallest run from nothing to a result is
short: install, build a world, spawn a set, order that set, step, read the tick,
the hash and one column. That is the worked example the orientation document
already holds.[^4] It deliberately covers no window, no pyramid, no selector, no
fixed-point scale, no threading model, no figure, and no agent server, and it
explains why nothing.

**Four how-to guides.** Install and build the extension. Repeat a run exactly.
Read what one tick did without walking the population. Order a set with one
command. Each names a goal a reader arrives with, and each maps onto a call on
the surface today. A fifth goal, drawing a frame through the camera, is held
back until the four publish, because a reader who cannot install cannot draw.

**The explanation quadrant is three pages and it mostly links out.** Section 5
gives that decision in full.

**The order is justified against the reader, not against the symmetry of the
framework.** The reference is first because it is the only quadrant that cannot
decay quietly, because it answers the cost the product record calls the sharpest
— what a call returns and which error it raises, currently answerable only from
a Rust file — and because the other three cite it.[^5] The doc comments follow,
because the reference publishes empty prose until they exist and the generated
page is what makes each gap visible. The example harness comes before the prose,
because a page written before it is a page nobody ever runs. The explanation is
last because it is the smallest, and because reading the earlier quadrants
decides how much of it is needed. The name check is last because it compares
against a published site.

**What checks it.** Four things, and each fails rather than reports. The build
fails when the import fails. Every example is executed. The public name list is
derived from the package and compared against the site. The stub and the module
agree, which item 0307 owns and which runs before all of it.

Eleven numbers were reserved. Eight were used. Three were not, because the plan
needs eight items and inflating the count would have produced items nobody could
refine.

| 0309 | `refined/` | The site, the generated reference and the publishing job. |
| 0310 | `proposed/` | The Rust doc comments the reference publishes. |

**0316, 0317 and 0318 are unused.** A number is never reused, so a later writer
may take them.

**Two items are refined and six are proposed.** 0308 and 0309 carry a complete
architectural impact review, decision by decision, with the governing records,
the blockers and the precedent named. The other six state why they are not
refined, and in every case the reason is the same shape: the finish line depends
on an artefact that item 0309 has not built yet. Marking them refined would have
been a claim rather than a review. Item 0314 has a second reason: an open choice
must close first.

Every item names PRD-0021 in its `serves` field.[^5]

## 3. How each of the four decisions was honoured

**D1, the published reference is generated by an import of the compiled
module.** No item in the plan writes a reference page. Item 0309 adds one
directive that names the compiled module and a member filter, and the plan says
in its own words that planning the reference means planning a build. The
research report measured which unwanted members an import collects, and 0309
cites that measurement rather than repeating the figures.[^6]

**D2, the prose lives in the Rust doc comment and nowhere else.** The prose gap
is item 0310, and that item is work in the bindings crate. It reads the
generated page, and for each public member it asks three questions: does prose
exist, does it state the return and its unit, and does it name the errors. The
record states in its own consequences that a doc comment written for the Rust
reader alone under-serves the Python developer and that no check can see it, so
the item is a reading task and not a check.

**D3, the stub declares types and carries prose only where the module provides
none.** No item writes into the type stub and no item moves prose into it. Item
0307 already holds the generator, the two checks and the removal of the eleven
copied docstrings, and the plan orders itself behind it rather than repeating
it.[^7] The plan states the reason the priority index already gives: a reference
built over two declaration sites publishes whichever site the tool reached.

**D4, the job builds the extension first and fails when the import fails.** Item
0309 owns the job. It compiles the crate, installs the module, then builds the
site. It never sets the option that turns module inspection off. The item also
requires somebody to prove the failure: turn inspection off behind a temporary
change and confirm the job fails, because a guard that has never fired has not
been shown to exist.[^8]

**The record needed no change.** Nothing in the plan contradicts it, and this
work asks for no amendment.

## 4. The duplicated docstrings

**Item 0307 owns them, and this plan did not take them.** Eleven docstrings in
the type stub copy prose the Rust source owns: nine exception docstrings that
agree character for character, one class docstring that agrees, and one that
drifted and dropped the paragraph warning against one value in two places.[^9]

Two reasons for leaving them with 0307. The first is that the removal is
inseparable from the generator and the second check that keeps them removed, and
0307 holds both. Splitting the removal from its check would leave the tree
clean and unprotected. The second is ordering rather than ownership: 0307 must
close before any documentation build starts, so the copies are gone before the
first page publishes, and no item in this plan ever meets them.

**The plan states that dependency in three places**: the order section of 0308,
the precedent field of the impact review in 0309, and the new priority rows. The
priority index already carried the reason, and the rows do not restate it in new
words.

## 5. The explanation quadrant

**It mostly links out, and that was the conclusion rather than the starting
assumption.** This repository holds 71 decision records, 21 product records, a
research report corpus and three registers. Copying any of it into a site
creates a second declaration site for a fact whose original lives elsewhere,
with nothing that fails when the copies disagree, which is the shape this
project names first in its own rule.[^10] The product record refuses the copy
for its own reason: it says that documenting the records and the reports is not
part of the need, because both have their own homes and pulling them in would
give the need no bound.[^5]

**Three pages survived the test, and each is a translation rather than a copy.**
The rule that Python sends one command and does not walk a population, together
with the plain statement that nothing enforces it. What determinism gives the
reader and what it does not, because a deterministic defect passes both
determinism tests. Which surface a program may depend on, and what is missing.
The product record requires all three by name. A record states each for a
contributor to this project; none of them is stated for the reader who will
break it.

Everything else is a footnote that names a record.

## 6. The registers

- **Findings.** Two rows added. FND-322 records that the orientation document
  sells a level 2 the pyramid does not hold, while the project instruction file
  says in bold that level 2 does not exist and the Rust source names it in the
  conditional. FND-323 records that the same document sells the agent server as
  a product capability and gives the command that starts it, while the protocol
  library is a development dependency the package never installs, so a reader
  who follows the document gets an import error. The next-number line advanced
  by two in the same change.
- **Decisions.** DEC-114 opened, with three options and a recommendation. It
  asks how a published page cites a repository document a reader cannot open.
  The recommendation is to publish the documents the site actually cites, from
  the files that already hold them, limited to those documents. That is the only
  option that adds neither a second copy nor a second citation form. Item 0314
  waits on it. **No decision record was written, and none is asked for.**
- **Blockers.** BLK-035 opened. Nobody in the tree can say where the site
  publishes or who turns the publishing on. The owner is the project owner. Item
  0309 states the address as a parameter and cites the row.
- **Registry.** Untouched. No record was written and no number allocated.
- **Priority index.** All eight items placed in the `Next` group, directly
  under 0307, in the order the plan states.

## 8. What was left undone

- **No documentation exists.** No page, no site, no navigation, no
  configuration, no workflow and no dependency was added. That was out of scope,
  and the items hold it.
- **Six items are not refined.** Each says why, and in every case the reason is
  that the finish line depends on the site that 0309 builds.
- **DEC-114 is open.** The recommendation is written and nobody has chosen.
- **BLK-035 is open**, and only the project owner can close it.
- **FND-322 and FND-323 record two false claims and repair neither.** The
  orientation document still states them. Neither repair belongs to a planning
  item, and item 0244 already holds the wider problem that the two orientation
  documents disagree.[^11]
- **The record is a draft.** ADR-0107 binds nothing until a reviewer accepts it,
  and this plan is written against a draft.
