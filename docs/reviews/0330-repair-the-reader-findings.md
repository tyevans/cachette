# Item 0330, the repair of the reader findings (report)

This document reports one unit of work. A developer who was given the address
of the published Python reference, and nothing else, read it six times and
graded it against seven dimensions. This work repaired what that review found.

Every repair went into a Rust doc comment. A record binds the provenance of the
reference prose: the page is generated by an import of the compiled extension
module, and the prose of a member that module provides lives in the Rust doc
comment of the bindings crate.[^1] No page was edited to repair a page, except
the site index, which is written prose and not generated.

## 1. Each repair, and the grade it targets

### First action, graded 1 of 5. The constructor

**What the reader met.** No constructor entry. No parameter list. No seed, no
faction count. The reader could not write the third line of a five-line
program.

**What was done.** The parameters of the `World` constructor and of the
`Camera` constructor now sit in the doc comment of their class, under a heading
that names the call. Each gives the parameter, its type, its default and its
bound. The doc comment on the constructor function itself now says where the
prose lives and carries none of it, so the two sites cannot part.

**Why the class and not the constructor.** The binding library replaces the doc
comment of a constructor with the standard interpreter sentence. A register
recorded the mechanism before a reader met it.[^2] A decision register row holds
the three options and the reasoning.[^3]

**Confirmed rendered.** The built page carries the heading "Build a world", the
signature line, and the four parameters.

### Gaps, graded 2 of 5. Orientation and the way in

**What the reader met.** Two links, neither of which is documentation. No
install line. No statement of whether a tutorial exists.

**What was done.** The module doc comment now names the audience in one
sentence, gives four commands that build the package from a checkout, and says
plainly that this reference is the whole documentation site today. The site
index carries the same install block.

**One thing the repair had to say and could not check.** No public package
index carries this engine, and the obvious name belongs to an unrelated
project. A finding holds the evidence and a blocker holds the two missing
facts.[^4] [^5]

### Vocabulary, graded 2 of 5. The `kind` collision

**What the reader met.** One word naming two integer scales that overlap at 0,
1 and 2, and a third name, `commodity`, whose relation to either was not
stated.

**What was done, and what was deliberately not done.** The prose is repaired.
The interface is unchanged.

The module doc comment now states that the two scales are separate, that they
overlap, that a member which takes a resource kind accepts an overlapping
ground kind, and that nothing reports it. The gather verb entry repeats it at
the call site and states the true guard: the refusal covers three and above.
The site economy entry states that a commodity is a third scale, that the world
holds one commodity, and that its number is zero.

**The old prose described a guard that cannot fire on the overlapping range.**
That claim is removed rather than preserved. A finding records it.[^6]

**The interface question is recorded and not answered.** A decision register row
holds four options and recommends making a kind a distinct type at the
boundary, on the ground that the project already made that decision for an
entity identity.[^3] A backlog item holds the work and waits on that row.[^7]

### Values, graded 3 of 5

`tile_values` already stated in the tree that each entry is a Q16.16 raw
integer, and the returned mappings already carry key lists. Those repairs
landed before this work and the review read an older page. The remaining value
repair was the census radius: the entry now says that the radius counts tiles,
gives the default as 8, and gives the ceiling as 64.

### Orientation, graded 3 of 5, and Trust, graded 3 of 5

The audience sentence above answers the first. The second was one hard internal
contradiction: the configuration error class said that the `World` constructor
raises it and named "the world settings", a term used nowhere else. That entry
now names the arguments, names the two bounds a caller meets first, and points
at the class doc comment that lists every argument. Documenting the constructor
repaired the contradiction at its source.

### Failure, graded 4 of 5. The radius ceiling

The verb error class now gives the ceiling of a window census as a radius of 64
tiles, and the census entry gives the same number. The configuration error is
now preventable, because the constructor arguments are documented.

### Two defects the review did not name

Two doc comments carried an empty `# References` heading before an `# Errors`
heading. The page rendered both as visible empty sections, and the page
contents list showed them. Both are removed.

## 2. The constructor parameters, and where each default was read

Every value below was read from the source and then checked through the public
interface.

| Parameter | Value | Read from |
|---|---|---|
| `World.width` | default 64, at least one | The signature attribute of the constructor; the refusal was checked by calling with zero |
| `World.height` | default 64, at least one | The same |
| `World.seed` | default 81985529216486895 | The signature attribute, which writes it in hexadecimal as `0x0123_4567_89ab_cdef` |
| `World.faction_count` | default 4, ceiling 63, zero legal | The signature attribute for the default; the ceiling and the zero case were checked by calling |
| `Camera.tile_size` | default `None`, which gives 12.0 pixels, held to 2.0 to 64.0 | The opening tile constant and the clamp of the viewer crate; both bounds were checked by calling |
| `window_census.radius` | default 8, ceiling 64 | The signature attribute for the default; the census module constant for the ceiling, checked by calling at 64 and at 65 |
| `site_economy.commodity` | default 0, and zero is the only member | The signature attribute for the default; the commodity count of the site module, checked by calling at 0, 1 and 2 |

**Each of those numbers is now a second declaration site.** The code owns them
all. A test reads every one through the public interface and fails when the
code moves it.[^8]

**The test was shown to fail.** Six of the documented numbers were perturbed at
once, and five of the eight tests failed. The two that did not fail are the
commodity test and the overlapping kind test, whose constants are zero and the
tuple 0, 1, 2, and the perturbation did not reach them. A backlog item holds the
work that would derive the list rather than write it.[^9]

## 3. What was recorded rather than fixed

**DEC-120, open.** Does a resource kind stay a bare integer at the Python
boundary, or become a distinct type? Four options, with the recommendation to
make a kind a distinct type and to reject the cheaper renumbering, because the
kind numbering reaches the state hash. The row also records the second question
the reader raised: whether the guard is missing rather than merely
mis-described.

**BLK-040, open.** Under which name does a reader install the package, and does
the project publish it? The project owner owns both facts.

**FND-340.** The reference cited an error that a call it never published
raises, and a fresh reader could not write the third line of a program. It
records that a member which carries prose is not a member a reader can use, and
that the guard on the documentation build counts presence and cannot count
sufficiency.

**FND-341.** The name a reader would install belongs to an unrelated project.

**FND-342.** The check that a gather order documents cannot fire on half the
numbers a caller confuses, and the wrong answer repeats exactly, so neither
determinism test can see it.

**DEC-121, closed.** Where does the prose of a constructor live, when the
binding library publishes none? The doc comment of the class holds it.

**Backlog.** Item 0330 is complete. Items 0331, 0332, 0333 and 0334 are
proposed, and each has a row in the priority index.

## 5. What is left undone

**The rubric the review was graded against is not in the tree.** The brief named
a path for it and no file is there. The repairs were made against the review
itself, which quotes the page for every finding and states the repair that
reaches the next grade. A backlog item writes the rubric down before a second
round runs.[^10]

**Nothing has re-read the repaired page as a fresh reader.** The rendered page
was read to confirm that each repair appears, and that is not the same
measurement.

**The returned mappings were not re-examined against the review.** The typed
dictionaries that carry their keys landed before this work, and the review read
an older page. A second round should say whether the keys now answer.

**Three dimensions cannot reach 5 from the reference alone.** The review asked
for a runnable example, a tutorial and a link to a guide. Three other items own
those pages, and this work wrote none of them.
